# 0005. Code structure and conventions

Status: Accepted
Date: 2026-11-23

## Context

The project has several services that are measured and scaled separately, a React console, and load-test tools. The repository is public and is meant to be read.

## Decision

### Layout

```
cmd/ingest       reads the source, produces to the raw topic
cmd/normalize    raw topic -> channel-agnostic events in the events topic
cmd/conv         builds conversations, keeps live state in Redis
cmd/router       queues, assignment, SLA timers, PostgreSQL
cmd/sim          simulated operators
cmd/gateway      WebSocket API for the console
cmd/record       tool: writes the raw topic to files for load tests
cmd/replay       tool: plays a recording into the raw topic at a chosen speed
internal/        one package per area, for example source, bus, conv, route, gateway
web/             React console (Vite, TypeScript)
docs/decisions/  these records
deploy/          Dockerfiles and compose files
```

One binary per service. Each one has its own container, memory limit and metrics endpoint.

### Go conventions

- Go 1.27. The same version in `go.mod`, CI and Dockerfiles.
- Packages by area, not by layer. A `main` package only reads configuration, builds dependencies and runs.
- Small interfaces declared where they are used. Dependencies are passed through constructors. No global state.
- Standard library first: `net/http` with the Go 1.22 router, `log/slog`, `context`, `errors`.
- Kafka through `franz-go` (pure Go). Builds run with `CGO_ENABLED=0` and produce static binaries.
- PostgreSQL through `pgx` with queries generated by `sqlc`. Migrations with `goose`.
- Errors are wrapped with `%w` and returned. No panics outside `main`.
- Every goroutine has an owner and stops on context cancellation. Services shut down gracefully.
- Configuration comes from environment variables and is validated at start.

### Tests and checks

- Table-driven unit tests, run with the race detector.
- Bus code is tested against the in-memory fake Kafka cluster from `franz-go`. Integration tests use real services through Testcontainers: Kafka, PostgreSQL and Redis.
- CI runs `go vet`, `golangci-lint`, tests with `-race`, and `govulncheck`.
- Test data is synthetic.

### Observability

- Each service exposes Prometheus metrics and `pprof`.
- Tracing is not added at the start. It gets its own decision record if it is needed.

### Frontend

- Vite, React, TypeScript, TanStack Query, Zustand, Tailwind CSS, TanStack Virtual for long lists.
- The console is built to static files and served by nginx.

## Consequences

- Six services mean six Dockerfiles or one multi-target Dockerfile, and more configuration than a single binary with roles.
- `pgx` and `sqlc` keep SQL visible, which matters for the locking queries in the router.
- Integration tests need Docker locally and in CI.
